The one-paragraph version

Ali built the team harness: a Claude Code plugin with 13 Sadie skills, an always-on EC2 box, a Slack gateway where one thread is one session, and nightly sweeps. I built a personal operating system on top of Lauren Tan's pstack: a hook that makes rigor fire on every session without asking, a memory system that survives sessions, a cost ruler that routes every subagent to the cheapest tier that can succeed, and the tooling to keep it all honest. Put together they cover the whole lifecycle of an agent at Sadie: how it starts, how it works, what it remembers, what it costs, where it runs, and how the team reaches it. Separately, each has a hole the other fills. I propose we merge them under one name, keep the two authorships visible, and ship it as the plugin every Sadie engineer installs.

What kingstack contributes to minions

This is the larger half of the value, and it maps onto things minions already wrote down as wanted.

Ignition

  • A SessionStart hook in the plugin injects fleet rules and the pstack contract into every session, laptop or box.
  • Makes "every minion, every session" true instead of aspirational.

Memory (ROADMAP §4)

  • Stop-hook distiller → inbox → /memory-review → per-project banks with provenance and tests.
  • Their rule "corrected three times = missing skill line" is what the inbox operationalizes.

Process engine (ROADMAP §2b)

  • The four pstack verbs they want, plus the other 39, via sync-pstack.sh: zero maintenance, upstream keeps flowing.
  • Pushback on "steal ideas, don't install": the sync script is why installing costs nothing.

Cost and bounds

  • Routing ruler: gateway and timers pick model per class of work; every headless run gets --max-turns.
  • Usage ledger for the box; today it has zero visibility.

Two risks worth naming, as a colleague

Prompt-injection surface on the box. The gateway feeds the entire Slack thread text from any workspace member into a bypassPermissions session on a machine holding admin AWS profiles, DB creds, and Slack tokens; feat-watch reads prod guest transcripts into a skip-permissions session with a posting token. The allowlist gates who can trigger, not whose text gets read. Read-only is an env var, not a boundary. The IAM README is honest; the injection path is not called out anywhere.

Fix in the merge: per-thread scoped allowlists (the pattern run-sweeps.sh now uses), read-only IAM as the default credential in the session not just the profile name, and treat any external text as data.

No run bound on the gateway. No --max-turns, no timeout, failures never surface, .sessions.json grows forever. And the phone engine is plain HTTP on port 80 with the bearer token in the URL.

Fix: the routing ruler's bound discipline, a per-thread ceiling, TLS via caddy (already on Ali's next list).

The name

sadiestack. It says what it is and where it sits: pstack is Lauren's engine, kingstack is one person's operating system on it, sadiestack is the team's. The lineage stays readable in the name. Alternates if that reads too plain: groundwork (Sadie already uses the word for its seed architecture; risk of collision) or foreman (the one who runs the crew; less self-explanatory). I would pick sadiestack and move on.
